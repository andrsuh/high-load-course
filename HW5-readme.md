Кейс #5 будет состоять из трех последовательных тестов. На этом мы закроем с вами тему back pressure и пойдем дальше. В
прошлом кейсе я намекал вам на возможность
“поиграть” с очередью запросов. В этом я предлагаю оставить очередь в покое и обратить внимание, что rate-limiter может
быть использован не только при обращении к внешней системе, но и на входе в ваше приложение. Мало того, некоторые
рейт-лимитеры предполагаю в своей реализации возможность регулировать очередь входящих запросов. Ментор попросит вас
объяснить, почему вы выбрали именно такой алгоритм и параметры лимитера в каждом случае.
Вы уже знаете пару алгоримов, например, скользящие и фиксированные окна. Скользящее окно даже сможет вам помочь, если
поиграть с его параметрами. Будет интересно, если вы поэкспериментируете со “составными” рейт-лимитерами (class
CompositeRateLimiter к вашим услугам, можете менять его, как хотите, например заменить конъюнкцию результатов лимитеров
на дизъюнкцию). Ну и пару новых алгоритмов выложу позже.

Тест 1:

Аккаунт: "acc-23"
Тест:
{
"ratePerSecond": 15,
"testCount": 3000,
"processingTimeMillis": 2500
}
Тест 2:

Аккаунт: "acc-23"
Тест:
{
"ratePerSecond": 11,
"testCount": 2200,
"processingTimeMillis": 13000
"profile": "s_0.7_60"
}

Буквальный смысл параметра “profile”: “s_0.5_30” для решения кейса понимать не обязательно. Но обязательно заметить на
графиках, чем этот кейс отличается от предыдущих. Важно в этом кейсе - не переусердствовать, отрезая часть запросов,
ведь покупатели могут и не вернуться. Также обратите внимание, что максимальный rps = 11 для аккаунта асс-23 должен быть
полностью, а не частично использован.
Ориентир на результаты теста:
Время выполнения 3.5 минуты
Fail / Success - 42 / 2230
Income / Expenses - 892k / 68k

Тест 3:
Аккаунт: "acc-23"
Тест:
{
"ratePerSecond": 3,
"testCount": 1050,
"processingTimeMillis": 26000
"runits": 90
}

Rps == 3 в данном случае не станет простой прогулкой.
Опять же - для нас важно увидеть на графике, что мощность аккаунта утилизируется на 100%. Об этом будем судить по
графику (Online shop > Payment system) http requests processed rate (rps).
Ориентир на результаты теста:
Время выполнения 6 минут
Fail / Success - 2 / 1060
Income / Expenses - 428k / 31.9k
